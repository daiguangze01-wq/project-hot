## 1. 验证问题、口径与边界

### 1.1 要回答的问题（来自 `validation/README.md` TASK-060）

1. 固定 45–55° 正交、pitch 50°、yaw 45°、size 7–9、H=1.8m 时，角色是否 70–90px @1080p？
2. 6/10/14m 战斗距离是否在视口内、是否可测？
3. 20/30m 是否必须 zoom-out？docs/02 的 size 15/23 够不够？
4. 默认 size / pitch / yaw 建议？

### 1.2 本验证是什么、不是什么

| 是 | 不是 |
|---|---|
| 固定正交投影的纯数学模型（可复现、可 assert 校验） | Unity/URP 实际渲染（无引擎、无后处理、无遮挡、无 LOD/AA） |
| 合成 PIL 渲染：几何/构图/标注是否可读 | 最终美术验收、像素风资产可读性 |
| 「目标是否在屏内 / 屏幕多大」的几何判断 | 「90%/85%/80% 测试者 1 秒识别」的 playtest 结论 |
| 决策级证据（M0 前筛掉几何上不可行的方案） | 玩家手感、PvP 公平性、性能 |

**关键边界**：本报告的「可读性」只指**几何可见性**（在屏内、未被裁切、像素尺寸），不包含 occlusion/雾/特效遮挡/色弱/玩家经验。合成图里的角色是**几何占位模型**（方盒拼装，含帽/肩/武器/影子），不是美术资产。

### 1.3 判定口径

- **屏幕**：1920×1080（16:9），默认缩放 **1.0×**（70–90px 只对默认缩放定义，见 §4）。
- **角色高度**：`H_eff = 1.8m` —— **含帽子与武器的有效剪影高度**（与 docs/02 §3.1、docs/04 §4 同口径）。同时输出 `H_body = 1.5m` 列以暴露 docs/00 的「1.5m 基准」冲突。
- **「在视口内」三种方向口径**（CSV 中均有列）：
  1. `inside_forward`：从屏幕中心沿**相机前方**（屏幕竖直中线向上）的地面距离 d 的脚点是否在 1080p 画面内。这是最严格、也是战斗中最常用的「目标在正前方」情形；
  2. `inside_world_axis`：沿**世界 +X 轴**（yaw=45° 时相对屏幕为 45° 对角）的地面距离 d 的脚点是否在画面内——代表 8 方向键位中「横/竖」轴上的战斗距离；
  3. `inside_any_direction`：是否存在**任意**地面方向使 d 处脚点入屏（等价于 d ≤ 可见地面矩形半对角）。这是最宽松上界。
- **脚点 vs 全身**：主表判「目标脚点是否在屏内」；「全身可见」（脚点 y − 角色屏高 ≥ 0）更严格，报告中单列。
- 距离均从**玩家/屏幕中心**量起；**未包含相机前移（camera lead）**，因为基线文档未定义 anchor。相机前移的定量影响见 §5.2。

## 2. 方法

### 2.1 投影公式（与 TASK-060 brief 完全一致）

```text
right   = ( cos(yaw),            -sin(yaw),            0          )
up      = ( sin(yaw)sin(pitch),   cos(yaw)sin(pitch),   cos(pitch) )
forward = ( sin(yaw)cos(pitch),   cos(yaw)cos(pitch),  -sin(pitch) )

u = dot(p, right);  v = dot(p, up)
screen_x = W/2 + u*scale;  screen_y = H/2 - v*scale
scale = 1080 / (2*orthoSize)      # px per metre @1080p
```

`run.py` 里实现了该公式，并在 `main()` 内做 assert 自检：
- 角色屏高 `H_eff·cos(pitch)·scale`；
- 屏幕四角沿 `forward` 投射到 z=0 得到可见地面多边形，其相机轴半宽/半深与闭式解 `half_width = W·S/H`、`half_depth = S/sin(pitch)` 误差 < 1e-9；
- 10m 正前方点的直接投影与解析式一致。

### 2.2 可见地面（屏幕四角投射 z=0，脚本输出）

| 量 | 解析式（16:9, 1080p） | size 7 | size 8 | size 9 |
|---|---|---|---|---|
| 可见地面半宽（相机右方向） | `W·S/H = 16/9·S` | 12.444 m | 14.222 m | 16.000 m |
| 可见地面半深（相机前方向） | `S/sin(pitch)`，pitch 50° | 9.138 m | 10.443 m | 11.749 m |
| 可见地面半对角（任意方向最大半径） | `sqrt(half_w² + half_d²)`，pitch 50° | 15.439 m | 17.645 m | 19.850 m |
| 世界 X/Y 轴可见距离（yaw=45°） | `min(half_w, half_d)/cos45°`，pitch 50° | 12.923 m | 14.769 m | 16.615 m |

> 16:9 的横向视野是纵向的 1.778 倍，所以「侧向/对角」永远比「正前方」看得远。**正前方半深才是 6/10/14m 战斗的瓶颈。**

### 2.3 合成图方法（PIL）

- 2× 超采样后用 LANCZOS 降采样到 1920×1080；文字/UI 在 1× 层绘制保证清晰。
- 内容：1m 世界网格（5m 主格线）、6/10/14m 距离环（20/30m 虚线环在 inset 中）、3 个简化角色（腿/躯干/**肩甲**/头/**帽**/**武器** + 地面**影子**，总高恰 1.80m）分别位于正前方 6/10/14m、**1.8m 高度条**、70–90px 标尺、俯视示意 inset、**1:1 角色剪出条**（正交下同一尺寸，用于检查帽/肩/武器/影子是否可辨）。
- 图内固定标注 **"SYNTHETIC MODEL RENDER - NOT UNITY"**、参数、seed、公式与限制。种子 20261017 只用于地面碎点纹理；两次独立运行输出字节一致（sha256 见 §7）。

### 2.4 输出 `metrics.csv`

15 行 × 35 列：9 行 shipped（size 7/8/9 × pitch 45/50/55）+ 6 行 zoom-out（size 15/23 × pitch 45/50/55）。关键列：`char_px_H_eff_1.8m`、`within_70_90`、`band_delta_px`、`char_px_body_1.5m`、`ground_half_width_m`、`ground_half_depth_m`、`ground_half_diag_m`、`world_axis_visible_m`，以及每个距离 d∈{6,10,14,20,30} 的 `forward_feet_y_px` / `inside_forward` / `inside_world_axis` / `inside_any_direction`。

**解读**：
- 6m 在所有参数下都在屏内，且 6m 目标在默认下脚点 y=230px，屏幕位置舒适。
- 10m 在默认 size 8 下脚点 y=23px：**只露出脚/腿，头顶被上边缘裁掉约 55px**；只有 size 9 能「全身」看到 10m（全身可见上限 10.24–10.93m）。

- 若 yaw=0（世界轴与屏幕轴对齐），14m 正前方仍然必然出屏；因此 **yaw 是必须固定并写入基线的参数**（当前 docs/00/02/04 均未写 yaw，属于待补项）。

### 3.4 20/30m 与 zoom-out

docs/02 §3.1 规定 20/30m 用 zoom-out size 15/23。模型核对：

| viewport | size | pitch | char px | 半深 m | 半对角 m | 20m 正前脚点 y | 30m 正前脚点 y |
|---|---:|---:|---:|---:|---:|---|---|
| zoom20 | 15 | 45° | 45.8 | 21.213 | 34.075 | **yes** (31) | no |
| zoom20 | 15 | 50° | 41.7 | 19.581 | 33.084 | **no (−11.6)** | no |
| zoom20 | 15 | 55° | 37.2 | 18.312 | 32.349 | no (−49.8) | no |
| zoom30 | 23 | 45° | 29.9 | 32.527 | 52.248 | yes (208) | **yes** (42) |
| zoom30 | 23 | 50° | 27.2 | 30.024 | 50.728 | yes (180) | **yes** (0.4，贴边) |
| zoom30 | 23 | 55° | 24.2 | 28.078 | 49.601 | yes (155) | no (−37.0) |

**解读**：size 15/23 显然是用 `S = d·sin(pitch)`（p50：20×0.766≈15.3，30×0.766≈23.0，取整）反推的**「目标脚点恰好贴上边缘」**尺寸，因此：
- pitch 45° 有余量（20m 脚点 y=31px；30m y=42px），pitch 50° 勉强（20m 差 11.6px 出屏、30m 脚点 y=0.4px 贴边），pitch 55° 都不够（差 49.8 / 37.0px）；
- 即使脚点入屏，**身体仍被裁**（size 15 角色仅 41.7px、size 23 仅 27.2px，头顶必然在屏外）——与 docs「20/30m 仅战术/轮廓、不作战斗验收」的定位一致，但「轮廓」实际上只剩腿/下半身。

**需要的 size（脚本 [B] 段）**：

| 目标 | 只要求脚点入屏 | 全身可见 + 24px 上边距 |
|---|---:|---:|
| 20m，pitch 45/50/55° | 14.14 / 15.32 / 16.38 | 16.13 / 17.24 / 18.23 |
| 30m，pitch 45/50/55° | 21.21 / 22.98 / 24.57 | 23.53 / 25.26 / 26.80 |
| 14m 正前（shipped 视角参考） | 9.90 / 10.72 / 11.47 | 11.69 / 12.43 / 13.08 |

**结论**：20/30m **必然**需要 zoom-out（shipped size 7–9 任何方向都到不了 30m，20m 也仅在 size 9/p45 的角尖理论上可容）。但 docs 的 15/23 应改为**按 pitch 计算的公式**：`S ≥ d·sin(pitch)`（脚点贴边）或 `S ≥ (d·sin(pitch) + 1.8·cos(pitch))·1080/1032`（全身+24px 边距）。pitch 50° 下建议 20m→**16–17**、30m→**24–26**（按口径），或保留 15/23 但 zoom 档同时使用相机前移 anchor（§5.2 同法）。

## 5. 建议

### 5.1 默认参数（不改基线）

| 参数 | 建议 | 理由 |
|---|---|---|
| ortho size | **8**（范围 7–9 保留） | 78.1px 在 70–90 带中央；size 7 虽 89.3px 但正前方可见深度仅 9.14m；size 8 为 10.44m |
| pitch | **50°**（45–55° 保留为风格测试范围） | 45° 偏大（size 7→98.2px），55° 偏小（size 8→69.7px）且可见深度更差；50° 是唯一让 size 7–8 都落在带内的中位值 |
| yaw | **45°** 并写入基线 | 世界 X/Y 轴对称为视口对角，14m 沿战斗轴可贴边可见；yaw=0 时 14m 正前必然出屏 |
| zoom | 默认 **1.0× 固定** | 0.8×/1.2× 会分别把 78.1px 变成 62.5/93.7px，破坏 70–90px 口径 |

> 任何默认值变更属于相机基线变更：按 `docs/04 §4` 末尾与 AGENTS §9，需走 **ADR-002 复访 + Human 批准**，本报告只提建议。

### 5.2 若 14m 战斗/可读性必须成立（三种方案，按推荐顺序）

前提：默认 8/50 正前方脚点只到 10.44m、全身只到 8.93m。要让 14m 正前方目标进入画面：

| 方案 | 做法 | 代价 | 定量 |
|---|---|---|---|
| **A. 相机前移（推荐，若确定要 14m）** | 玩家 anchor 从屏幕中心下移到屏幕高度 60–77% 处（camera lead 2.5–4.9m） | 后方可见变少；属于相机基线变更，需 ADR-002 复访 | 14m **脚点**入屏：size 8/p50 anchor ≥ **0.670**（前方 13.99m / 后方 6.89m）；14m **全身**+24px：anchor ≥ **0.765**（后方仅 4.91m）。pitch 45° 更宽松：size 8/p45 全身 anchor **0.720**（后方 6.32m）；size 9/p45 全身 **0.643**（后方 9.09m，且 char=76.4px 仍在带内） |
| **B. 不改相机，14m 只作「边缘指示/小地图」信息** | 14m 锁定目标用屏幕边缘指示器 + 小地图；可读性验收只覆盖 6/10m | 玩家对 14m 威胁只有方向感，无剪影信息 | docs/00 §3.1 已有「屏幕边缘 目标/队友/危险指示器」；建议把 docs/02 §3.1 的 14m 行改为「边缘指示 + 方向」，或限定测试时 14m 目标置于屏幕四角方向 |
| **C. 加专门 zoom-out 战斗档（size 10–12）** | +/- 缩放到更远 | size 10/p50 char=62.5px，低于 70–90px；破坏「角色可读性」口径 | 不推荐作为战斗档；可作为观察/战术档，与 20/30m 战术档同一定位 |

**推荐**：默认保持居中相机 + 方案 B（与现有边缘指示器设计一致）；若 Human/Design 认为 14m 战斗距离是核心，则选 A，并把 anchor（如玩家屏幕高度 67%）写入相机基线/TDD，同时接受后方可视性缩短到约 6.9m（size 8/p50）。

### 5.3 zoom-out 尺寸建议

把 docs/02 的固定 15/23 改为**按 pitch 推导**（同一公式）：

```text
脚点贴边：      S >= d * sin(pitch)
全身+24px 边距： S >= (d * sin(pitch) + H_eff * cos(pitch)) * 1080 / (1080 - 48)
```

| 距离 | 脚点贴边（p45/50/55） | 全身+24px（p45/50/55） | 建议取整（p50，全身） |
|---|---|---|---|
| 20m | 14.14 / 15.32 / 16.38 | 16.13 / 17.24 / 18.23 | **17**（或 16 若只要求脚点） |
| 30m | 21.21 / 22.98 / 24.57 | 23.53 / 25.26 / 26.80 | **26**（或 24 若只要求脚点） |

补充：zoom 档角色屏高 size 15 = 41.7px、size 23 = 27.2px，仅够「战术轮廓」；这与 docs「不作战斗验收」一致，但建议在 UI 上明确 zoom 档不显示身份/装备细节。

## 6. 假设与限制

1. **模型 ≠ 引擎**：本报告是固定正交投影的数学结果，不含 URP 的渲染管线、阴影、后处理、AA、遮挡淡出、地形高差；真实画面可读性可能更好也可能更差。
2. **合成图 ≠ 美术**：角色是方盒占位模型，只验证「几何位置/尺寸/裁切」，不验证最终像素风资产的剪影/对比度/识别率。
3. **无 playtest**：docs/02 的 90/85/80% 识别率无法由本验证确认，只能作为 M0/M1 玩家测试目标。
4. **H_eff=1.8m 是假设**：取「含帽/武器有效剪影高度」；实际美术包围盒需在 Unity 中量测并回填公式。若取 1.5m，70–90px 结论改变（§3.1 末列）。
5. **yaw 假定 45°**：基线文档未定义 yaw，按 TASK-060 brief 的公式取 45°。若最终 yaw 不同，「世界轴可见距离」与 14m 对角可见性会改变（正前方结论不随 yaw 变）。
6. **相机居中假设**：所有「在视口内」判断假设玩家位于屏幕中心、相机无前移。若采用 camera lead（§5.2），需重跑本脚本（`run.py` 的公式可复用）。
7. **默认缩放 1.0×**：70–90px 只对默认缩放成立；0.8×/1.2× 分别产生 62.5/93.7px（size 8）。
8. **20/30m 的 15/23 来自 docs/02 假设**：本验证不判断该数值是否已被 Human 批准，只核对几何后果。
9. **方向口径**：主表以「正前方」为战斗主情形；「世界轴/任意方向」列用于说明侧向/对角差异。实际战斗距离是二维任意方向，因此「14m 是否可见」的答案天然是方向相关的。
10. **屏幕 16:9 专属**：半宽按 1920/1080 计算；其他宽高比只改横向，不改正前方纵深。
