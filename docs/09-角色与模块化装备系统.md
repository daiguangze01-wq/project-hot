# 角色与模块化装备系统（纸娃娃 / Paperdoll）

> 结论：你的判断对，这是业界标准的 **paperdoll / modular avatar / equipment slot** 系统。
> 我们的基线（ADR-010）本来就是 3D 低模 + 共享骨架 + 装备模块化；AI 生成“整套角色 + 整套动作”是错的方向，应该改成 **基础身体 + 可拆装备 + 固定 UV 纹理**。

## 1. 参考作品

| 作品 | 做法 | 对我们的启示 |
|---|---|---|
| 冒险岛 MapleStory | 基础身体 + 头发/脸/衣服/披风/武器分层；动作共享 | 纸娃娃的核心是“层/槽位”，不是整只角色 |
| 热血英豪 | 官方头像编辑：发型/脸/身体/服装；3D 预览 + 2D 贴图编辑；可上传自定义造型 | UGC 纹理/造型是可行卖点，但需审核 |
| 热斗传说 | 自由造型系统，上传自定义造型文件 | 玩家创作/交易可做，但要防违规/版权 |
| 3D MMO / Unity | 共享 skeleton + 模块化 skinned mesh/骨骼挂点 + 材质槽/atlas | 3D 路线成熟；适合自由转向/换装 |

## 2. 术语

- **Paperdoll / 纸娃娃**：角色由基础身体 + 可替换外观层组合。
- **Equipment slot**：`hair / face / head_accessory / top / bottom / shoes / gloves / cape / weapon_main / weapon_offhand`。
- **Skinned mesh**：跟随同一骨架变形的装备 mesh（衣服/头发）。
- **Socket / bone attachment**：挂在骨骼上的静态 mesh（武器/帽子/披风挂点）。
- **UV template**：装备的固定贴图布局；玩家只画颜色/花纹，不改几何。
- **UGC texture override**：把玩家上传的贴图应用到固定装备槽位；不是上传任意模型。

## 3. 推荐架构（3D 基线，符合 ADR-010/013）

```text
AvatarBase (shared)
  ├─ Body mesh + Skeleton + Animator（10 个共享动作）
  ├─ Face material / skin color
  ├─ Hair slot (skinned mesh or socket)
  ├─ Head accessory slot
  ├─ Top slot (skinned mesh)
  ├─ Bottom slot (skinned mesh)
  ├─ Shoes / gloves
  ├─ Cape slot (skinned/socket + optional cloth)
  ├─ Weapon main / offhand (socket; animation archetype by weapon type)
  └─ UGC material override per slot (fixed UV)
```

### 3.1 数据模型

```csharp
public enum AvatarSlot { Hair, Face, HeadAccessory, Top, Bottom, Shoes, Gloves, Cape, WeaponMain, WeaponOffhand }

[CreateAssetMenu]
public class AvatarItemDefinition : ScriptableObject {
  public string itemId;
  public AvatarSlot slot;
  public GameObject visualPrefab;     // skinned mesh or socket prefab
  public Material baseMaterial;
  public Texture2D defaultAlbedo;
  public Texture2D uvTemplate;        // 给玩家的模板
  public bool allowUgcTexture;
  public string[] hiddenBodyRegions;  // 例如穿长袍时隐藏腿部
}
```

- **外观与战斗核心分离**：`Core` 决定招式表（ADR-005）；`Weapon skin / clothes` 只决定外观。同一把武器可以有多个 skin。
- 武器类型（剑/枪/法杖）可复用共享骨架，但可以有各自的动画 archetype；不是每个 item 一套动画。
- 身体 mesh 只保留皮肤/基础内衣；衣服覆盖对应区域，避免“衣服和身体穿插”。

### 3.2 动画

- 一个 Animator，共享 10 个状态：`Idle/Walk/Run/Light/Heavy/RunLight/RunHeavy/Jump/JumpAttack/Guard`。
- 头发/披风用骨骼或 SpringBone/物理；衣服用 skinned mesh；武器挂手骨。
- 不生成“每个造型一套动作”；新增装备不应新增动画。
- 武器 archetype 差异（剑/枪/法杖）通过 **Animator Override / upper-body mask** 处理，仍共享基础移动。

### 3.3 UGC 纹理

- 每件可 UGC 的装备提供 `uv_template.png`（例如 256×256），玩家在模板上画 albedo/花纹。
- 运行时：校验尺寸/格式/文件大小 → 生成 `Texture2D` → 应用到该槽位材质实例。
- 服务器：存 hash/URL/审核状态；不在 MVP 直接信任客户端纹理；后续接 mod.io/Steam Workshop。
- 审核：举报/屏蔽/版权关键词/人工抽检；不允许上传几何/骨骼/可执行文件。
- 安全：限制像素尺寸、解码超时、内存上限；防止 zip bomb/巨图。

### 3.4 2D 纸娃娃备选（需要新 ADR 取代 ADR-010）

- 基础身体 + 头发前/后 + 脸 + 上衣 + 下装 + 鞋 + 披风 + 武器，全部同 canvas/pivot/帧号。
- 8 向 × 10 动作 × 每层帧数，资产量远大于 3D；排序/遮挡/换装复杂。
- AI 生成单件 layer 比整套角色可行，但 layer 对齐/动作一致仍是人工重活。
- 只作为风格样张；除非 Human 明确改向，不切换。

## 4. AI 在模块化管线里的正确位置

| 任务 | 推荐工具 | 产出 |
|---|---|---|
| 基础身体/发型/衣服**概念** | GPT Image / PixelLab / Midjourney | 概念图、色板、比例参考 |
| 2D 单件 layer（若走 2D） | PixelLab / Retro Diffusion | 透明背景、同 canvas 的头发/衣服层 |
| 3D 头发/武器/帽子 mesh | Meshy/Tripo + Blender 清理 | 低模、UV、骨骼挂点 |
| 衣服 mesh/skinning | 人工/Blender（AI 仅概念） | 与基础骨架匹配的 skinned mesh |
| 贴图/花纹/UGC 模板 | PixelLab / SD/Flux + Aseprite | 固定 UV 的 albedo/pattern |
| 完整角色 + 完整动作 | **不要用 AI 批量做** | 否决：不可换装/不可 UGC/成本爆炸 |

## 5. MVP 范围（U1）

- 1 个基础身体 + 共享骨架 + 10 动作。
- 2 发型、2 上衣、1 下装、1 鞋、1 披风、2 武器外观。
- 换装 UI/快捷键：至少 3 个槽位可切换。
- 1 个槽位的 UGC 纹理覆盖测试（本地 PNG → 材质）。
- 验收：换装不破坏动作/遮挡；同一动作下装备跟随；纹理替换不改变几何。

## 6. 对当前 U0/AI 的影响

- 停止“生成整只角色 + 10 动作”的 request；改为 **基础身体 + 单件装备 + UV 模板**。
- 之前 PixelLab 的 48×48 八向整身 idle 只能当 **风格/色板参考**，不能当生产资产。
- KayKit Knight 只作为共享骨架/动作占位；下一步需要 **基础身体**（可换装）和至少 1 套可拆装备。
- prompt bank/asset spec 要新增 `base_body/hair/top/bottom/shoes/cape/weapon/uv_template` 类别。

### 6.1 当前 U0 原型（2026-10-18）

- 统一基础身体/骨架/10 动作：暂用 KayKit Knight 占位。
- 已接 4 个槽：`HeadAccessory`（头盔）、`Cape`（披风）、`WeaponMain`（1H/2H 剑）、`WeaponOffhand`（3 种盾）。
- 本地 UGC 测试：`StreamingAssets/ugc/test_pattern.png` → `UgcTextureLoader` → 替换 body 材质贴图（128×128，限 2MB/1024px）。
- `AvatarChecks` PASS：4 槽切换 + UGC 读取。
- **缺**：真实可换的 base body/头发/上衣/下装 mesh；目前 KayKit 的衣服/身体是烘焙的，不能真正换装；需要 Phase 0 基础身体 + 单件装备。

## 7. 开放问题

1. 3D 基础身体用哪套 CC0 base mesh，还是自建/外包？
2. 武器 archetype 的动画复用策略（剑/枪/法杖各一套 upper-body clip？）。
3. UGC 纹理审核放在客户端提交前还是服务端；MVP 是否只做本地演示？
4. 2D 纸娃娃是否要做正式样张，还是只做 1 张概念图？
5. 装备 mesh 的遮挡/穿模规则（长袍隐藏腿、帽子隐藏头发等）。
